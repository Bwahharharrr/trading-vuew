# Plan: Multi-Tab Charts

_Generated by the multitab-charts-plan workflow (4 audits → synthesis), 2026-06-26._

## Feed decision
A (active-only-live). The feed audit and the code confirm CorkyFeed already has a single `dc` pointer plus a `_subs` Map and an `_activeSubId` gate (corky-feed.js:44,58,63) — only the most-recent subscription may mutate the cube. Strategy A is therefore a near-zero-delta extension of the existing invariant: one live subscription = the active tab; switching tabs re-points `corkyFeed.dc` to the active cube and re-subscribes (the gateway has no session resume, so a fresh subscribe is the existing reconnect path anyway). Strategy B (per-handle cube, N concurrent live streams over one socket) requires deleting the `_activeSubId` gate, per-handle liveness routing across many feed mutators (the audit calls it "highest risk, many-method per-handle surgery"), and risks back-pressure/reconnect-storm with ~400 live bars buffered per stream × N tabs over one socket — for no product-required benefit, since the user only ever looks at one chart at a time. A keeps each inactive tab as a correct static snapshot, which is exactly what a backgrounded browser tab should be. Concurrency can be added later behind the same ChartTab model without rework if a real need appears.

## Shared vs per-tab
PER-TAB (moves into the ChartTab record, one per open chart): the DataCube (`chart`) + its orderAgent + originalChartData; the active Corky stream identity (corkyCurrent, corkyHandle, corkyLast→folded into the tab) and the per-stream closure refs (_corkyGen, _corkyPendingRange, _corkyHistoryLoader binding, _corkyUnsub, the ride-through retry quartet _corkyRetryOpts/_corkySelectRetries/_corkyRetryTimer/_corkyRetryKeepSpinner); the on-chart overlay/derived state that lives on a specific chart — positionPlot, _btPlot + _btProgressSub, searchNav, priceAlarms (the list), and the drawing-tool armed state (rectDrawMode + in-progress OrderBox geometry); per-tab view UI (selectedView/displayedView/indicatorVisibility); and in FILE mode the loaded-file identity + that tab's WS connection and live buffers (currentDataFile/currentFileMeta/ws/_wsGen/liveScmrColors/liveAlertColors/liveZones/liveAlerts/liveDataStartIdx) and per-tf cube map (charts{}). APP-SHARED (stays singular on App): the corkyClient socket and the four feeds built over it (corkyFeed/positionsFeed/searchFeed/backtestsFeed) and corkyStates catalog; the entire bottom dock data (openPositions/historicalPositions/positionsAccounts, searchTabs/searchTabSeq, backtests strategies/runs/filters/selectedRun, audit*) and the dock's own internal tab system (positionsActiveTab); the discovery panel content; the overlay CLASS list passed to <trading-vue :overlays>; the alarm audio singleton (_alarmSound) and the single 500ms _alarmTimer poll loop (now scans the active tab, plus optionally all tabs); corkyEnabled (already keyed by venue|symbol, so two tabs on the same symbol intentionally share enabled indicators); and app layout (panelWidth, positionsDock*, window size, log_scale). The bridge rule: every dock/discovery click TARGETS a tab — single-click = the active tab, the new-tab gesture = a freshly created tab; the shared feeds route their one live stream to whichever cube is active.

## ChartTab model
ChartTab = { id: string (monotonic 'ct-N', stable for :key and persistence), title: string (derived 'SYMBOL · TF', recomputed on select), chart: DataCube (the per-tab cube; orderAgent hangs off it as chart.orderAgent), feedMode: 'gateway'|'file', corkyCurrent: {venue,symbol,timeframe,indicators,layers}|null, corkyHandle: subscription-handle|null, corkyLast: {venue,symbol,timeframe}|null (restore key), originalChartData: rawPreColoringData|null, selectedView: string, displayedView: string, indicatorVisibility: object, priceAlarms: [], positionPlot: {…}|null, btPlot: {runId,venue,symbol,timeframe,report,window,runIndex}|null, btProgressSub: handle|null, searchNav: {tabId,index,loading,…}|null, rectDrawMode: bool, file: {currentDataFile,selectedDataFile,currentFileMeta,charts:{},ws,_wsGen,live*…}|null (gateway tabs leave null), _stream: { gen:number, pendingRange:{start,end}|null, unsub:fn|null, retryOpts:object|null, retries:number, retryTimer:id|null, retryKeepSpinner:bool, historyLoaderBound:bool } (non-reactive per-stream closure state, markRaw so Vue doesn't proxy the retry timers/handles) }. App gains `chartTabs: ChartTab[]`, `activeChartTabId: string`, computed `activeTab` and `activeChart = activeTab.chart`. An empty/fresh tab is a ChartTab with a blank DataCube, corkyCurrent=null, title 'New Chart', showing the discovery panel as the call-to-action (no candles). MAX_CHART_TABS = 8 (each gateway tab = one cube = one live worker on activate; bounded to keep worker/watcher count sane — see risks); the '+' new-tab button and discovery/dock new-tab gestures are disabled past the cap with a tooltip.

## Phases

### Phase 1 — Lifecycle hardening: make a DataCube safe to create, background, and destroy N times
**Goal:** Fix the per-cube leaks that single-chart tolerated but multi-tab multiplies, WITHOUT changing single-chart behavior. This is the root-cause prerequisite: today every tab would leak a Worker + 3 root watchers.

**Files:** src/helpers/dc_core.js, src/helpers/dc_events.js, src/helpers/datacube.js, src/TradingVue.vue, test/component/render-trigger.test.js (new sibling test)

**Changes:**
- dc_core.js destroy(): after unwatching settings/ids/datasets, call this.ww && this.ww.destroy() (terminate the per-cube worker created in DCEvents ctor), null this.tv, and clear this.loader. Guard each (cube may be standalone).
- Add a teardown_tvjs() to DCCore as the inverse of init_tvjs (detach the 3 $watch hooks, leave data intact) so a backgrounded tab's cube can stop recomputing the settings fingerprint against the shared TradingVue root on blur — called later by the activate path; in Phase 1 it's just defined + unit-tested.
- TradingVue.vue: confirm set_loader/onrange stores exactly one closure (it does, :423) — add a clear_loader() so tab-switch can repoint it. No behavior change yet.
- Verify DCCore.destroy is idempotent (double-destroy safe) since tab-close + beforeUnmount can both fire.

**Validation:** npx vitest run (all 187+ green; add a unit test asserting destroy() terminates the worker and a second destroy() is a no-op) + typecheck + lint + build + size (floor unchanged). Existing single-chart Corky flow untouched.

**Risk:** LOW. Pure teardown additions; the only behavioral change (worker termination on replace) was already the intended semantics — single-chart just replaced the worker soon enough to mask the leak.

### Phase 2 — Two-tab proof: ChartTab model + tab bar + active-cube swap (manual new-tab only)
**Goal:** Deliver a working 2-tab chart with a top tab bar, switching, and the active tab rendering — even though only a manual '+' new tab exists. Single-chart Corky still works as 'tab 0'.

**Files:** src/App.vue (data, computed, template bind, chart watcher split), src/components/ChartTabBar.vue (new, mirrors the dock's selectTab pattern), src/mixins/app/chart-tabs.js (new mixin: createTab/activateTab/closeTab + activate wiring), test/component/chart-tabs.test.js (new)

**Changes:**
- Introduce chartTabs:[ChartTab], activeChartTabId, computed activeTab/activeChart. Seed tab 0 from the current new DataCube() so boot is identical. Bind <trading-vue :data="activeChart" :key="activeChartTabId"> for a clean per-tab remount (fresh range/shaders/crosshair — the audit's safest correctness story).
- Split the single `chart` watcher (App.vue:582-627) into TWO explicit code paths in chart-tabs.js: (a) onTabCubeReplaced(tab,newCube,oldCube) — destroys ONLY the replaced cube, rebuilds that tab's orderAgent/log_scale/alarm+position overlays; (b) activateTab(id) — re-points the SHARED corkyFeed.dc, tv.onrange loader, window.dc/window.tv, and re-applies log_scale to the now-active cube, and crucially NEVER calls destroy. The old.destroy() at :594 moves into path (a)/closeTab only.
- chart-state.js:258/281/293 + file-manager.js:144 change `this.chart = new …` → onTabCubeReplaced(activeTab, new …) targeting the active slot. Add a `chart` getter/setter shim on App (get→activeChart, set→replace active tab's cube) so the ~50 existing `this.chart` reads keep working unchanged this phase (incremental migration; removed in Phase 4).
- ChartTabBar.vue: tabs + active highlight + '+' button (createTab → blank gateway cube, activate) + per-tab close [x] (closeTab → destroy that cube, activate a neighbor; last tab can't close). Disable '+' at MAX_CHART_TABS=8.
- activateTab also calls teardown_tvjs on the outgoing tab's cube and init_tvjs on the incoming (or relies on remount) so background tabs don't keep live fingerprint watchers.

**Validation:** New component test: mount App with the harness, create a 2nd tab, switch, assert (a) activeChart points at the 2nd cube, (b) switching back does NOT destroy either cube (spy on destroy), (c) closing a tab terminates its worker. Manual: open 2 tabs, one charting BTC, '+' blank tab, switch — first tab's candles survive. Full gate: vitest + typecheck + lint + build + size.

**Risk:** MEDIUM. The watcher split is the load-bearing change; the `chart` get/set shim contains blast radius to one phase. :key remount per switch pays a re-init cost — acceptable, and avoids carrying stale range/last_candle across tabs.

### Phase 3 — Central click→intent router: single=current tab, gesture=new tab
**Goal:** Wire the new-tab trigger through ONE router instead of editing six row templates. Discovery-timeframe click + a modifier/middle-click on dock rows open a new tab; plain click targets the active tab.

**Files:** src/composables/useOpenIntent.js (new — tiny click/dblclick/modifier→{mode} normalizer), src/App.vue (one onOpenIntent router; route discovery select / position / search / bt-plot through it), src/components/feed/CorkyDiscoveryPanel.vue (tag timeframe emit mode:'new-tab'), minimal edits to CorkyPositionsPanel.vue / SearchResults.vue (bind the shared handler, not per-event templates)

**Changes:**
- useOpenIntent(payload, ev) → emits a single `open` with mode:'current'|'new-tab'. Mechanism choice (avoids the 250ms click/dblclick coexistence tax called out in the audit): discovery TIMEFRAME chip is already a distinct element → always mode:'new-tab' (per the user's spec). For positions/search rows keep single-click INSTANT = current tab, and use Ctrl/⌘-click or middle-click = new tab (browser-tab idiom, zero timing conflict). No global 250ms defer.
- App.onOpenIntent(intent): mode==='current' → activateTab(activeId) path then corkySelect on the active tab; mode==='new-tab' → createTab() then corkySelect on the new tab. corkySelect(opts) gains a tabId/tab param (defaults to active) so it operates on that tab's handle/current/cube/_stream.
- Discovery isCurrent/current highlight + positionsCurrentSymbolKey become 'does ANY/active tab show this symbol' — derive from activeTab.corkyCurrent.
- Backtest run-row select stays dock-only (opens detail); only the Plot button / trade rows navigate a chart, targeting the active tab (or the tab that holds that plot).

**Validation:** Component tests: (1) discovery tf click creates a new tab charting that venue/symbol/tf and leaves the prior tab intact; (2) plain position-row click navigates the ACTIVE tab (count stays); (3) ⌘/middle-click opens a new tab. Assert no double-navigation flicker (single click fires exactly one corkySelect). Full gate.

**Risk:** MEDIUM. The intent must resolve 'which tab' before any await; reuse the per-tab _stream.gen (Phase 4) to prevent a mid-select tab switch from cross-applying. Modifier-click is discoverable via tooltips ('⌘-click → new tab').

### Phase 4 — Per-tab stream + overlay state migration (corkyCurrent/handle + _stream + positionPlot/_btPlot/priceAlarms/searchNav)
**Goal:** Move every per-stream and on-chart-overlay field off the flat App instance into the ChartTab record so background tabs don't bleed into the active one. This is the correctness heart of the feature.

**Files:** src/App.vue (corkySelect, _corkyUnsub, _corkyHistoryLoader, retry quartet, syncPositionOverlays, ensurePriceAlarmOverlay, btPlotRun/btSelectTrade/btSelectCandidate, onSearchResultSelect, checkPriceAlarms), src/mixins/app/* (read/write tab fields via activeTab or an explicit tab arg)

**Changes:**
- Relocate corkyCurrent/corkyHandle/corkyLast + _corkyGen/_corkyPendingRange/_corkyUnsub + the retry quartet into tab._stream / tab fields. corkySelect uses tab._stream.gen as its staleness epoch (per-tab) so concurrent selects across tabs no longer supersede each other.
- _corkyHistoryLoader: register per-tab via tab.chart.onrange, closing over THAT tab (its corkyCurrent + _stream.gen) — fixes the audit's 'background tab backfills the active symbol' bug. activateTab repoints tv.onrange to the active tab's loader.
- positionPlot, btPlot/btProgressSub, searchNav, priceAlarms, rectDrawMode → tab fields. syncPositionOverlays/ensurePriceAlarmOverlay/_btPlot draw onto the TARGET tab's cube. Dock actions (shared dock) resolve the target tab (active by default) then mutate that tab's overlay state.
- checkPriceAlarms: scan the ACTIVE tab's alarms (decision: active-only — background-tab alarms pause; documented; the single _alarmTimer + _alarmSound stay shared). corkyEnabled stays app-shared (already symbol-keyed).
- Remove the temporary `chart` get/set shim from Phase 2; replace remaining `this.chart` reads with this.activeChart / explicit tab refs.

**Validation:** Component tests: two gateway tabs on DIFFERENT symbols — (a) panning tab A backfills A's symbol not B's; (b) plotting a position/backtest from the dock lands on the active tab only; (c) a price alarm set on tab A doesn't render on tab B; (d) a slow select on tab B resolving after switching to tab A does NOT clobber A (per-tab gen). Full gate + the existing golden/visual/stress suites stay byte-identical for the single-tab path.

**Risk:** MEDIUM-HIGH. Largest surface. Mitigate by migrating one field-cluster at a time, each commit gated, asserting the single-tab golden masters never move (single tab = old behavior exactly).

### Phase 5 — Persistence + polish: persist the tab set, restore on reload, file-mode tabs, UX edges
**Goal:** Extend the existing save/load to persist chartTabs + activeChartTabId; back-compat-upgrade the legacy single corkyLast/selectedDataFile into a one-tab list. Polish new-tab/empty/close UX and file-mode multi-tab.

**Files:** src/mixins/app/file-manager.js (saveStateToStorage/loadStateFromStorage), src/App.vue (boot restore in mounted), src/components/ChartTabBar.vue (empty-tab CTA, close/confirm, overflow), src/mixins/app/ws-manager.js (file-mode WS per tab), test/unit/persistence.test.js (new)

**Changes:**
- Persist a per-tab list: each entry {feedMode, corkyLast OR selectedDataFile, selectedView, indicatorVisibility} + activeChartTabId. Keep corkyEnabled/log_scale/panelWidth/positionsDock* app-global (localStorage) as today. Tab list goes to localStorage (survives restart) keyed alongside corkyLast.
- loadStateFromStorage: if the new tabs[] is absent but a legacy corkyLast/selectedDataFile exists, synthesize a single tab from it (zero data loss for existing users). Boot restore rebuilds N tabs, re-subscribes ONLY the active tab (active-only-live); inactive tabs restore lazily on first activate.
- File-mode multi-tab: move the WS + live buffers into tab.file so two file tabs each own their ws/_wsGen/live*; dataFiles list stays shared. Gateway tabs leave tab.file null.
- UX: empty tab shows discovery as the CTA; closing the active tab activates a neighbor; closing the last tab resets it to empty rather than removing it; '+' and new-tab gestures disabled past MAX=8 with tooltip; tab titles = 'SYMBOL · TF' (or 'New Chart').

**Validation:** Unit: legacy single-state localStorage round-trips into one tab; a 3-tab state restores 3 tabs with the active one re-subscribed and others lazy. Component: reload restores tabs; close-last resets to empty. Full gate (vitest + typecheck + lint + build + size). beforeUnmount destroys ALL tab cubes (worker-leak assertion across N tabs).

**Risk:** LOW-MEDIUM. Persistence back-compat is the one trap — covered by an explicit legacy-upgrade unit test. File-mode multi-WS is additive and gated; if scope-risky it can ship gateway-only first and file-multi-tab as a follow-on.

## Risks
- The chart watcher's old.destroy() (App.vue:594) is the single most dangerous line to carry forward — Phase 2 splits replace-semantics (destroy the replaced cube) from activate-semantics (never destroy). A tab switch must NEVER call destroy or it wipes a backgrounded tab.
- N tabs = N per-cube Workers + N×3 root $watch hooks unless Phase 1 lands first. DCCore.destroy must terminate the worker (this.ww.destroy()) and teardown_tvjs must detach watchers on tab blur; MAX_CHART_TABS=8 bounds the worst case.
- Active-only-live means switching tabs RE-FETCHES history (a brief flicker) and inactive tabs are frozen snapshots (no live updates while backgrounded). This is the deliberate trade for simplicity/safety; if a user needs a backgrounded tab to stay live, that's the Strategy-B follow-on, not a bug.
- Click/dblclick 250ms coexistence is avoided entirely by using the already-distinct discovery timeframe element for new-tab and modifier/middle-click for dock rows — NOT a global single-click defer (which would tax every single-click with latency).
- Per-tab staleness: _corkyGen/_corkyPendingRange/_corkyUnsub must become per-tab (tab._stream) or a slow select on one tab can clobber another, and a background tab's onrange loader can backfill the active symbol. Phase 4 fixes this; until then Phase 2/3 keep a single active stream so the invariant holds.
- Naming collision: 'tab' already means the bottom-dock tab (positionsActiveTab) and a search tabId. The new concept is named chartTabs/activeChartTabId throughout to avoid handler/payload confusion.
- Persistence back-compat: existing users have a single-shape localStorage (corkyLast/selectedDataFile). loadStateFromStorage must upgrade it into a one-tab list or reloads lose the user's chart — covered by an explicit legacy test.
- The single-tab golden/visual/stress masters must stay byte-identical: with exactly one tab the app must behave EXACTLY as today, which is the regression gate for every phase.

## Open questions
- Backgrounded-tab price alarms: should a price alarm on an INACTIVE tab still fire (requires the 500ms poll to scan all tabs, and re-subscribing/peeking inactive streams to get live prices — contradicts active-only-live), or pause until that tab is active? The plan assumes ACTIVE-ONLY (pauses); confirm that's acceptable, because all-tab firing meaningfully changes the feed model toward Strategy B.
- Backtest 'Plot' from the shared dock: should plotting a run always target the ACTIVE chart tab, or open a NEW tab for the run (so the dock detail and the chart stay aligned)? The plan defaults to active-tab; an explicit 'Plot in new tab' affordance is the alternative — this is a product/UX fork, not a default I should silently pick.
- MAX_CHART_TABS=8 and the file-mode-multi-tab inclusion in Phase 5: is 8 the right ceiling given each gateway tab activation spins a worker + a fresh subscribe, and is per-tab FILE-mode WS in scope now or a follow-on? If gateway-only multi-tab is acceptable for v1, Phase 5 shrinks and de-risks.
